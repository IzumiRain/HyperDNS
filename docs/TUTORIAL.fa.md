## ۰. قبل از شروع به چه چیزهایی نیاز دارید

۱. **یک سرور مجازی (VPS)** — حداقل ۱ هسته و ۱ گیگابایت رم (به جدول سخت‌افزار README مراجعه کنید). تارگت‌های تست‌شده Debian 12 و Ubuntu 24.04 هستند. نصاب با firewalld/ufw و systemd هم کار می‌کند.
۲. **یک دامنه** که مالک آن هستید و به پنل DNS آن دسترسی دارید. حداقل یک رکورد A به سمت سرور باید بسازید. چون مرجع گواهی باید بتواند سرور را ببیند، دامنه باید عمومی باشد.
۳. **این پورت‌ها روی سرور آزاد باشند** — هیچ سرویس دیگری نباید روی آن‌ها گوش دهد:

   | پورت | پروتکل | کاربرد |
   | ---: | :--- | :--- |
   | **۵۳** | UDP + TCP | دی‌ان‌اس ساده (چیزی که کنسول‌ها و روترها تنظیم می‌کنند) |
   | **۸۰** | TCP | پراکسی SNI برای HTTP + لیسنر چالش ACME |
   | **۴۴۳** | TCP | پراکسی SNI برای HTTPS (ترافیک واقعی بازی) |
   | **۸۵۳** | TCP | DNS-over-TLS («Private DNS» اندروید، iOS) |
   | **۸۴۴۳** | TCP | DNS-over-HTTPS |
   | **۸۰۸۰** | TCP | داشبورد مدیریت |

   اگر ارائه‌دهندهٔ شما فایروال ابری جداگانه دارد (Hetzner / OVH / Vultr)، آن پورت‌ها را **آنجاهم** باز کنید — فایروال خود سرور کافی نیست.
۴. **دسترسی root.** نصاب در `/etc/systemd/system/`، `/etc/systemd/resolved.conf.d/` و `/opt/hyperdns` می‌نویسد.

> ⚠️ **قبل از اینکه سرور را به اینترنت عمومی متصل کنید، [SECURITY.md](SECURITY.md) را بخوانید.** مدل تهدیدات، جزئیات رمزنگاری و چک‌لیست سخت‌سازی آنجاست.

## ۱. نصب هایپردی‌ان‌اس

### ۱-آ. نصب آنلاین با یک خط

<div dir="ltr">

```bash
curl -fsSL https://raw.githubusercontent.com/IzumiRain/HyperDNS/v2.2.0-beta.1/scripts/install.sh | sudo bash
```

نصاب در صورت وجود ترمینال تعاملی است. برای کاملاً اسکریپتی‌کردن:

```bash
curl -fsSL https://raw.githubusercontent.com/IzumiRain/HyperDNS/v2.2.0-beta.1/scripts/install.sh \
  -o install.sh

# ضروری: دامنهٔ پنل، و یک ایمیل برای مرجع گواهی
HYPERDNS_DOMAIN=dns.example.com \
HYPERDNS_EMAIL=you@example.com \
sudo bash install.sh
```

</div>

### ۱-ب. نصاب چه می‌کند (و از چه چیزی سر باز می‌زند)

- باینری نسخهٔ پین‌شده را دانلود، تأیید و در `/opt/hyperdns/` نصب می‌کند و سرویس systemd به نام `hyperdns` را ثبت می‌کند.
- **یک رمز عبور تصادفی** و **یک مسیر مدیریت ۱۶ نویسه‌ای تصادفی** تولید کرده و هر دو را **دقیقاً یک بار** چاپ می‌کند. همین حالا آن‌ها را در یک مدیریت رمزعبور کپی کنید — رمز عبور هرگز ذخیره نمی‌شود و قابل بازیابی نیست، فقط قابل تغییر.
- گواهی Let's Encrypt برای دامنهٔ پنل را **خودش**، روی لیسنر پورت ۸۰ خودش صادر می‌کند. نه certbot، نه acme.sh، نه توقف سرویس. اگر صدور ناموفق باشد، دلیل را چاپ کرده و خارج می‌شود — هرگز روی یک نصب خراب پیام موفقیت نمی‌دهد.
- **هیچ‌وقت درجا ارتقا نمی‌دهد.** اگر نصب قبلی پیدا کند، آن را در `/root/hyperdns-preinstall-<date>.tar.gz` آرشیو می‌کند (با چاپ sha256 آن — تنها کپی از داده‌های قدیمی) و بعد کامل جایگزین می‌کند: کانفیگ تازه، اعتبارنامهٔ تازه، گواهی تازه. در حالت تعاملی باید کلمهٔ `FRESH` تایپ شود تا پاک‌سازی تأیید گردد؛ و در حالت `curl | bash` به‌جز با `HYPERDNS_FRESH=1` اصلاً قبول نمی‌کند.
- `systemd-resolved` را کنار می‌گذارد (چون روی 127.0.0.53:53 می‌نشیند و پورت ۵۳ را می‌گیرد) با یک فایل drop-in در `/etc/systemd/resolved.conf.d/hyperdns.conf` و دسترسی‌های ایمن (دایرکتوری `755`، فایل `644`).

> **از HyperDNS 1.x می‌آیید؟** اول `bash migrate-from-v1.sh` (از باندل آفلاین) را اجرا کنید، بعد نصب کنید.

### ۱-پ. نصب آفلاین (بدون هیچ اینترنت خروجی)

باندل آفلاین را از صفحهٔ ریلیز بگیرید — باینری، نصاب، اسکریپت انتقال و تمام فایل‌ها را در خود دارد و با sha256 خودش را راستی‌آزمایی می‌کند. روی سرور کپی کنید و:

<div dir="ltr">

```bash
tar xzf hyperdns-v2.2.0-beta-linux-amd64-offline.tar.gz
cd hyperdns-offline
HYPERDNS_DOMAIN=dns.example.com HYPERDNS_EMAIL=you@example.com sudo bash install.sh
```

</div>

اسکریپت `verify_bundle.py` داخل باندل، چک‌سام همهٔ فایل‌ها را پیش از اعتماد دوباره بررسی می‌کند.

### ۱-ت. بررسی روشن‌بودن سرویس

<div dir="ltr">

```bash
systemctl status hyperdns
hdns status
```

</div>

`hdns status` نیازی به دسترسی دیتابیس ندارد و کنار دیمن در حال اجرا امن است. وضعیت سرویس، اینکه کدام لیسنر روی کدام پورت جواب می‌دهد، یک کوئری زندهٔ دی‌ان‌اس، و دامنهٔ پنل و وضعیت گواهی را گزارش می‌کند.

## ۲. اولین ورود — دو راز را ذخیره کنید

داشبورد **هیچ‌وقت** در ریشهٔ دامنه سرو نمی‌شود. در یک مسیر مخفی قرار دارد:

<div dir="ltr">

```text
https://<panel-domain>/<admin-path>/login
```

</div>

- `<admin-path>` همان رشتهٔ ۱۶ نویسه‌ای تصادفی است که نصاب یک بار چاپ کرد. اگر گمش کردید: `hdns status` آدرس داشبورد را نشان می‌دهد، و دیمن آن را در هر بار استارت در ژورنال دوباره چاپ می‌کند (`journalctl -u hyperdns | head`).
- نام کاربری `admin` است. رمز عبور همان رشتهٔ تصادفی نصاب است.

دو نکتهٔ مهم دربارهٔ صفحهٔ ورود:

- این صفحه **هیچ‌یک** از فایل‌های سنگین داشبورد را بارگذاری نمی‌کند، پس سورس داشبورد پیش از احراز هویت خوانده نمی‌شود.
- فیلد کد دومرحله‌ای **فقط** بعد از رمز عبور درست ظاهر می‌شود. رمز اشتباه هرگز نشان نمی‌دهد که 2FA روشن است.

آدرس را بوک‌مارک کنید. بعد بلافاصله به **Settings → Administrator Credentials** بروید و رمز قابل‌به‌خاطر‌سپاری بگذارید (یا بهتر، رمز تصادفی را در مدیریت رمزعبور نگه دارید و **Two-Factor Authentication** را در همان بخش فعال کنید).

## ۳. آشنایی با داشبورد

ساید‌بار هفت بخش دارد؛ این آموزش همهٔ آن‌ها را می‌بیند:

| تب | مسیر | کاربرد |
| :--- | :--- | :--- |
| **Dashboard** | `/home` | تله‌متری زنده: نمودار QPS، مشترکین فعال، نرخ برخورد کش، تأخیر هر آپ‌استریم. |
| **Clients** | `/clients` | افزودن/ویرایش/حذف مشترکین، سهمیه، انقضا، لینک ثبت و رمز ثبت. |
| **Policy Presets** | `/rules` | سوییچ‌های ۱ کلیکی برای ۱۷۱+ بازی و سرویس، به‌علاوهٔ لیست‌های کاستوم. |
| **Live Stream** | `/logs` | استریم زندهٔ کوئری‌های دی‌ان‌اس روی SSE، با برچسب اکشن هر کوئری (`PROXY`، `DIRECT`، `BLOCK`). |
| **API** | `/api` | ساخت کلید Master API، نمونه‌کد آماده، بررسی وضعیت انتشار عمومی. |
| **Settings** | `/settings` | حالت لیست سفید، پالیسی‌ها، بایندینگ API، 2FA، LDAP، مسیر مخفی مدیریت، **Subscription Portal**، SSL/TLS. |
| **Connect Guide** | `/guide` | دستورالعمل اتصال به‌ازای هر پلتفرم، برای فرستادن به مشترک. |

در پایین ساید‌بار هم **آی‌پی عمومی سرور** (کلیک برای کپی)، دکمهٔ **Run Diagnostics**، دکمهٔ **Restart** (ری‌استارت موتور و بارگذاری مجدد قوانین)، دکمهٔ **Flush Cache** و **Sign Out** قرار دارد.

## ۴. دامنهٔ پنل و HTTPS

اگر `HYPERDNS_DOMAIN` را به نصاب داده‌اید این کار انجام شده — مستقیم بروید [گام ۵](#۵-دامنهٔ-کاستوم-برای-لینک-مشترکین-sub). وگرنه:

۱. در پنل DNS دامنهٔ خود یک **رکورد A** برای هاست‌نیم پنل بسازید، مثلاً `dns.example.com. A <server-IP>` با TTL برابر ۳۰۰.
۲. در داشبورد: **Settings → SSL / TLS Manager for DoH, DoT (Android Private DNS)**. دامنه و ایمیل ACME را تنظیم کنید و auto-cert را فعال کنید.
۳. دیمن گواهی را خودش روی پورت ۸۰ صادر می‌کند و به‌صورت Hot-Swap در همهٔ لیسنرهای زنده جایگزین می‌کند — DNS-over-TLS روی ۸۵۳، DNS-over-HTTPS روی ۸۴۴۳، پنل مدیریت و پورتال مشترکین — بدون ری‌استارت و بدون قطعی. تمدید روزانه و خودکار است.

اگر صدور گواهی ناموفق بود، به این ترتیب بررسی کنید: رکورد A منتشر شده (`dig dns.example.com` از یک ماشین دیگر آی‌پی سرور شما را بدهد)، پورت ۸۰ تا انتها (شامل فایروال ابری ارائه‌دهنده) باز است، و هیچ سرویس دیگری روی پورت ۸۰ نیست.

## ۵. دامنهٔ کاستوم برای لینک مشترکین (sub)

اینجا همان بخشی است که بیشتر اپراتورها می‌خواهند: هر مشترک یک صفحهٔ شخصی می‌گیرد — وضعیت، سهمیه و ثبت آی‌پی — و به‌طور پیش‌فرض این صفحه روی دامنهٔ پنل سرو می‌شود. اگر سرویس می‌فروشید، احتمالاً می‌خواهید روی **دامنهٔ برند خودتان** باشد تا لینکی که به مشتری می‌فرستید `https://sub.yourbrand.com/sub/<token>` باشد، نه هاست‌نیم پنل مدیریت شما.

چون پورتال مشترکین یک لیسنر کاملاً جداگانه با تنظیمات TLS خودش است، دامنهٔ آن می‌تواند هر چیزی باشد — حتی دامنه‌ای از یک ثبت‌دامنهٔ متفاوت، یا ساب‌دامینه‌ای از دامنه‌ای که برای هیچ کار دیگری استفاده نمی‌کنید.

### ۵-آ. دامنه را به سمت سرور نشانه بگیرید

در پنل DNS:

<div dir="ltr">

```text
sub.yourbrand.com.   A   <server-IP>     TTL 300
```

</div>

از یک **هاست‌نیم اختصاصی** برای پورتال استفاده کنید. هاست‌نیم پنل را دوباره استفاده نکنید — این دو عمداً از هم جدا شده‌اند تا مشتری‌ای که در حال مرور پورتال است هرگز به صفحهٔ ورود مدیریت نرسد و برعکس.

### ۵-ب. در داشبورد تنظیمش کنید

**Settings → Subscription Portal**:

| فیلد | چه وارد کنید |
| :--- | :--- |
| **Enable subscriber portal** (`sub-enabled-input`) | روشن. |
| **Custom Subscription Domain** (`sub-domain-input`) | `sub.yourbrand.com` — **خالی یعنی «همان دامنهٔ پنل»**، که پیش‌فرض است. |
| **Advertised port** (`sub-port-input`) | برای ۴۴۳ خالی بگذارید (توصیه‌شده). فقط اگر پورتال باید روی پورت غیراستانداردی اجرا شود پر کنید. |
| **Portal title** (`sub-title-input`) | نام برند شما — به‌عنوان عنوان صفحه نشان داده می‌شود. پیش‌فرض `HyperDNS`. |

بعد روی **Issue SSL** (`sub-issue-ssl-btn`) کلیک کنید. یک نوار پیشرفت ظاهر می‌شود و دیمن دقیقاً مثل پنل، روی لیسنر پورت ۸۰ خودش برای آن هاست‌نیم گواهی صادر می‌کند — بدون توقف سرویس. وقتی تمام شد، روی **Save** (`save-subscription-btn`) کلیک کنید.

تمام شد. از این به بعد لینک هر مشترک روی `https://sub.yourbrand.com/sub/<token>` ساخته می‌شود.

> **فیلد پورت فقط لینک *نمایش‌داده‌شده* را تغییر می‌دهد.** خود لیسنر همیشه روی ۴۴۳ سرو می‌کند. این فیلد برای حالت‌هایی وجود دارد که یک CDN یا پراکسی معکوس جلوی سرور TLS را روی پورت دیگری ترمینه می‌کند؛ اگر چنین لایه‌ای ندارید، خالی بگذارید.

## ۷. مشترک چطور آی‌پی خود را ثبت می‌کند

بعد از ساخت یک کلاینت **دو چیز جداگانه** می‌گیرید، و این جداسازی عمدی است:

- **Subscription Link (portal page)** — آدرس، به فرم
  `https://sub.yourbrand.com/sub/<token>`. این را می‌توانید از تلگرام، واتس‌اپ یا پیامک بفرستید. هر کسی آن را باز می‌کند فقط **وضعیت و سهمیه**ٔ مشترک را می‌بیند — چیز دیگری نه.
- **Registration Secret** — یک رمز جداگانه. مشترک **آن را در صفحهٔ پورتال تایپ می‌کند** تا آی‌پی فعلی‌اش را به حساب متصل کند.

خود لینک به‌تنهایی برای ثبت کافی نیست. تمام منطقش همین است: یک لینک لو رفته نباید به یک غریبه اجازه دهد آی‌پی خودش را به یک حساب پولی وصل کند. لینک را در چت بفرستید، و رمز را از یک **کانال دوم** (یا تلفنی، یا اسکرین‌شات) برسانید.

### ۷-آ. از سمت مشترک

۱. `https://sub.yourbrand.com/sub/<token>` را باز می‌کند — روی **همان شبکه‌ای** که می‌خواهد ثبت شود، چون پورتال آی‌پی هر کسی که بازش می‌کند را می‌بیند.
۲. **Registration Secret** را وارد می‌کند.
۳. در پس‌زمینه این یک `POST /ip/<token>` حامل رمز است. دیمن رمز را بررسی می‌کند، آی‌پی مبدا را ثبت می‌کند، و حساب روشن می‌شود.

از همان لحظه، کوئری‌های دی‌ان‌اس از آن آی‌پی سرو می‌شوند. اگر آی‌پی مشترک عوض شد (دادهٔ موبایل، روتر جدید، سفر)، همان لینک را باز کرده و دوباره ثبت می‌کند — بدون نیاز به دخالت شما.

### ۷-ب. اگر خودتان Initial IP را تنظیم کردید

اگر **Initial IP Address** را هنگام ساخت پر کرده باشید، حساب از ابتدا متصل است و مشترک هیچ کاری باید نکند. برای مشتری‌ای که آی‌پی‌اش را می‌دانید (خط خانگی ثابت) استفاده‌اش کنید، و برای کاربران موبایل خالی بگذارید.

### ۷-پ. چرا آی‌پی ناشناس رد می‌شود

**لیست سفید (Whitelist) دسترسی کلاینت‌ها به‌صورت پیش‌فرض فعال است.** یک آی‌پی مبدا که به هیچ حسابی متصل نیست، یک رد دی‌ان‌اس همراه با **خطای RFC 8914 Extended DNS Error** می‌گیرد، تا کلاینتِ خوش‌رفتار دلیل مسدودی را بفهمد نه اینکه بی‌صدا شکست بخورد. یعنی یک سرور باز هرگز به زیرساخت رایگان عمومی برای غریبه‌ها تبدیل نمی‌شود. می‌توانید با **Settings → Client Access Whitelist Mode** خاموشش کنید، اما اول [SECURITY.md](SECURITY.md) را بخوانید — `allow_all` سرور را به یک ریسالور عمومی تبدیل می‌کند و پهنای باند آن را شما می‌پردازید.

## ۸. اتصال دستگاه‌ها

مشترک **یک عدد** — آی‌پی سرور — را به‌عنوان دی‌ان‌اس خود تنظیم می‌کند. نه اپ، نه پروفایل، نه VPN. تب **Connect Guide** (`/guide`) دستورالعمل به‌ازای هر پلتفرم تولید می‌کند که می‌توانید مستقیم در چت پیست کنید.

| پلتفرم | کجا تنظیم می‌شود |
| :--- | :--- |
| **ویندوز ۱۰/۱۱** | Settings → Network → Ethernet/Wi-Fi → Hardware properties → DNS server assignment → Manual → IPv4، و `8.8.8.8` را با `<server-IP>` جایگزین کنید. |
| **پلی‌استیشن ۴/۵** | تنظیمات → شبکه → تنظیم اتصال اینترنت → سفارشی → IP خودکار، DHCP Host: مشخص نشده، DNS: دستی — اصلی `<server-IP>`، فرعی `<server-IP>` (یا فرعی خالی). |
| **ایکس‌باکس Series X/S** | Settings → General → Network Settings → Advanced Settings → DNS Settings → Manual، هر دو فیلد `<server-IP>`. |
| **نینتندو سوییچ** | System Settings → Internet → Change Settings → DNS Settings → Manual، Primary `<server-IP>`. |
| **اندروید (Private DNS / DoT)** | تنظیمات → شبکه → Private DNS → «custom» → `dns.example.com` — از **پورت ۸۵۳** استفاده می‌کند، رمزنگاری‌شده. هاست‌نیم، نه آی‌پی. |
| **iOS / iPadOS** | یک پروفایل DoH، یا یک آی‌پی دی‌ان‌اس ساده در Settings → Wi-Fi → ⓘ → Configure DNS. |
| **روتر (کل خانه)** | DNS تخصیص‌یافته توسط DHCP در تنظیمات WAN/LAN روتر — تمام دستگاه‌های پشتش یکجا پوشش داده می‌شوند. |

ترانسپورت‌های رمزنگاری‌شده به **هاست‌نیم** نیاز دارند (یک گواهی را راستی‌آزمایی می‌کنند)، و حالت ساده به **آی‌پی**.

یک تست سریع از هر ماشینی:

<div dir="ltr">

```bash
# دی‌ان‌اس ساده به سمت سرور شما
dig @<server-IP> api.steampowered.com

# DNS-over-TLS (همان مسیر Private DNS اندروید)
kdig -d @dns.example.com +853 api.steampowered.com
```

</div>

اگر رکورد `A` جواب **آی‌پی خودِ سرور شما** باشد، یعنی پراکسی SNI آن اتصال را به دست می‌گیرد؛ اگر جواب آی‌پی واقعی CDN باشد، یعنی مستقیم می‌رود.

## ۹. روشن و خاموش کردن پریست‌های پالیسی

**Policy Presets**، ۱۷۱+ بازی و سرویس را در دسته‌بندی‌هایی با یک سوییچ برای هر کدام گروه‌بندی کرده. **همه به‌جز سه مورد پیش‌فرض روشن‌اند**:

- `enable_downloads` — نصب‌های چندگیگابایتی بازی. خاموش، چون ترافیک خروجی را گیگابایتی می‌پردازند و دانلود از طریق پراکسی معمولاً کندتر از مستقیم است. قبل از روشن‌کردن، پاراگراف «پیش از فعال‌سازی» در README را بخوانید.
- `enable_adblock` — مسدودسازی تبلیغات.
- `enable_familysafe` — فیلتر محتوای بزرگسال.

هر سوییچ دامنه‌هایی که پوشش می‌دهد را نشان می‌دهد. تغییرات بلافاصله روی موتور زنده اعمال می‌شوند؛ بعد از یک تغییر بزرگ، **Flush Cache** (ساید‌بار) یا `POST /api/v1/cache/flush` را بزنید تا پاسخ‌های کش‌شده تا پایان TTL مسیر قدیمی را نگه ندارند.

کاتالوگ کامل، به تفکیک دسته، در [PRESET_CATALOG.md](PRESET_CATALOG.md) است.

## ۱۰. مشاهدهٔ ترافیک زنده

**Live Stream** (`/logs`) یک استریم Server-Sent Events است — هر کوئری که سرور مدیریت می‌کند، زنده، با قانون منطبق و اکشن انجام‌شده:

- `PROXY` — جواب به آی‌پی سرور جعل شد تا پراکسی SNI اتصال را بگیرد. این رفتار گیت‌وی گیمینگ است.
- `DIRECT` — جواب واقعی، دست‌نخورده، بین آپ‌استریم‌ها مسابقه.
- `BLOCK` — سینک‌هول شد.
- `DIRECT · Game & App Downloads` — وتوی دانلودها در حال اجراست (گام ۹).

هیچ‌کدام از این‌ها هرگز روی دیسک نوشته نمی‌شوند. تله‌متری دی‌ان‌اس فقط در حافظه و روی همین استریم زندگی می‌کند — هیچ فایل لاگ کوئری‌ای برای لو رفتن وجود ندارد. اگر تب را ببندید، تاریخچه می‌رود.

**Dashboard** (`/home`) نمای تجمیعی است: نمودار QPS، نرخ برخورد کش، و تأخیر هر آپ‌استریم تا ببینید کدام ریسالور مسابقه را برده.

**Run Diagnostics** (ساید‌بار) لیسنرها را بررسی می‌کند، یک کوئری تست می‌زند، و وضعیت گواهی را گزارش می‌دهد — سریع‌ترین جواب به «خراب است یا نه؟».

## ۱۱. محدودیت‌ها، انقضا و مدیریت روزمرهٔ کلاینت

در **Clients**، هر سطر این‌ها را دارد:

- **Edit** — تغییر نام، سهمیه، سیکل، انقضا، آی‌پی‌های مجاز.
- **Reset Traffic** — صفرکردن بایت‌های مصرفی (همین کار با `POST /api/v1/clients/{id}/reset-traffic`).
- **Regenerate UUID** — UUID قدیمی را **فوراً** بی‌اثر می‌کند. همین که حس کردید لینکی لو رفته از این استفاده کنید: لینک قدیدی درجا می‌میرد و یک لینک و رمز تازه می‌گیرید.
- **Delete** — حذف دائمی.

دو رفتار مهم:

- **سهمیه فقط ترافیک پروکسی‌شده را می‌شمارد.** پاسخ‌های مستقیم رایگان‌اند، پس مشتری‌ای که سهمیه‌اش تمام شده باز هم می‌تواند مرور کند — فقط ترافیک پروکسی‌شدهٔ بازی متوقف می‌شود. شمارنده در RAM تجمیع و هر ۳۰ ثانیه در یک تراکنش روی دیسک نوشته می‌شود، چون هر تراکنش BoltDB یک `fsync` است.
- **انقضا یک توقف سخت است.** آی‌پی یک حساب منقضی مثل یک آی‌پی ناشناس رد می‌شود. برای تمدید، انقضا را ویرایش کنید، یا برای تمدید از طریق API، `PUT /api/v1/clients/{id}` با `days_to_add`.

## ۱۲. قوانین پیشرفته: کاستوم پروکسی / مسدود / مستقیم / رکوردهای استاتیک

در **Policy Presets**، زیر سوییچ‌ها، چهار لیست به شما اجازه می‌دهند همه چیز را بازنویسی کنید:

| لیست | اثر | کاربرد معمول |
| :--- | :--- | :--- |
| **Custom Proxied** | عبور این نام‌ها از پراکسی SNI. | یک بازی که در هیچ پریستی نیست؛ یا نجات یک مشترک گیر کرده روی یک CDN مسدود. |
| **Custom Blocked** | سینک‌هول این نام‌ها. از همه چیز بالاتر است. | تله‌متری، بازی‌ای که نمی‌خواهید پروکسی شود، دامنه‌های تبلیغاتی. |
| **Custom Direct** | اجبار به جواب واقعی، هرگز پروکسی نشود. | سرویسی که CDNش پراکسی‌ها را مسدود می‌کند، یا دامنه‌ای که نمی‌پردازید. |
| **Custom Records** | جواب‌های استاتیک دی‌ان‌اس که شما کنترل می‌کنید. | Split-horizon: `git.lab.example.com → 10.0.0.5` برای افراد داخل، جواب واقعی برای بقیه. |

تطبیق **طولانی‌ترین پسوند برنده** است، همراه با یک ایندکس تطبیق دقیق، پس `cdn.example.com` می‌تواند پروکسی شود در حالی که `*.example.com` مستقیم می‌رود — قانون خاص‌تر همیشه برنده. قوانین کاستوم روی **پلن یک کلاینت** روی قوانین سراسری لایه می‌شوند، و نام خاص‌تر همیشه تصمیم می‌گیرد.

## ۱۳. REST API و سواگر

هر کاری که در بالا انجام می‌شود قابل اسکریپت‌نویسی است. **Settings → API Network Binding & Security** کنترل می‌کند `/api/*` کجا گوش دهد (پیش‌فرض فقط `127.0.0.1` — همین جا نگه‌اش دارید مگر اینکه دلیل دارید بازش کنید)، و **Master API Authentication Key** کلید را تولید می‌کند.

مستندات تعاملی: **`/<admin-path>/api/v1/docs`** — Swagger UI، درون خود باینری تعبیه و از خود سرور سرو می‌شود، پس در شبکه‌های بدون دسترسی به CDN هم کار می‌کند. روی **Authorize** کلیک کنید، کلید Master API را پیست کنید، و هر اندپوینتی را از داخل مرورگر اجرا کنید.

نسخهٔ v2 قرارداد فعلی است (`/api/v2/…`): نام‌گذاری متقارن فیلدها (`display_name`، `allowed_ips`)، لیست‌های صفحه‌بندی‌شده بر اساس کرسر (`{items, next_cursor}`)، خطاهای استاندارد RFC 9457 `application/problem+json`، اندپوینت‌های اختصاصی `POST /clients/{id}/actions/{action}`، و **دیکود سخت‌گیرانه** — یک فیلد ناشناخته یک خطای ۴۰۰ است، نه یک اشتباه تایپی بی‌صدا. v1 هنوز کار می‌کند اما هدرهای `Deprecation` و `Sunset` را یدک می‌کشد. مرجع کامل با نمونه‌های Python / Node.js / cURL: [API.md](API.md).

ساخت یک مشترک با API:

<div dir="ltr">

```bash
curl -X POST "https://dns.example.com/<admin-path>/api/v2/clients" \
  -H "Authorization: Bearer $HYPERDNS_KEY" \
  -H "Content-Type: application/json" \
  -d '{"display_name": "Reza (PS5 & Phone)", "traffic_limit_gb": 100}'
```

```python
import requests

r = requests.post(
    "https://dns.example.com/<admin-path>/api/v2/clients",
    headers={"Authorization": f"Bearer {API_KEY}"},
    json={"display_name": "Reza (PS5 & Phone)", "traffic_limit_gb": 100},
)
client = r.json()
print(client["registration_link"])   # این را برای مشترک بفرستید
print(client["registration_secret"]) # این را از یک کانال دوم
```

</div>

> کلید Master API روی **تمام مسیرهای مدیریتی داشبورد رد می‌شود** — فقط روی `/api/*` کار می‌کند. این تفکیک در v2.2.0 اضافه شد تا یک کلید API لو رفته تبدیل به یک سشن ادمین نشود.

## ۱۴. کنسول `hdns`: وضعیت، پاک‌سازی کش، استارت/استاپ، حذف

<div dir="ltr">

```bash
hdns status      # گزارش زندهٔ سرویس: پورت‌ها، لیسنرها، تست دی‌ان‌اس، گواهی‌ها.
                   # نیازی به دیتابیس ندارد — کنار یک دیمن شلوغ امن است
hdns flush       # درخواست از دیمن در حال اجرا برای پاک‌سازی کش دی‌ان‌اس
hdns version     # چیزی که باینری چاپ می‌کند (مثلاً HyperDNS v2.2.0-beta)
hdns uninstall   # حذف تعاملی
```

</div>

کنسول تعاملی همچنین می‌تواند سرویس را **متوقف**، **استارت** و **حذف** کند — روی سروری که فقط کنسول سریال/SSH دارید و پنل وب در دسترس نیست مفید است.

معادل‌های systemd:

<div dir="ltr">

```bash
systemctl stop hyperdns      systemctl start hyperdns
journalctl -u hyperdns -f    # لاگ زندهٔ دیمن (آدرس داشبورد در هر استارت دوباره چاپ می‌شود)
```

</div>

## ۱۵. بک‌آپ و بازیابی

دو فایل تمام نصب شماست — همه چیز دیگر قابل بازتولید است:

| فایل | چرا مهم است |
| :--- | :--- |
| `/opt/hyperdns/data.db` | تمام وضعیت: مشترکین، سهمیه‌ها، قوانین، تنظیمات. |
| `/opt/hyperdns/master.key` | کلید ۳۲ بایتی AES-256-GCM که فیلدهای حساس را مهروموم می‌کند. |

<div dir="ltr">

```bash
# بک‌آپ
tar czf hyperdns-backup-$(date +%F).tar.gz \
  -C /opt/hyperdns data.db master.key
sha256sum hyperdns-backup-*.tar.gz
```

</div>

- **اگر `master.key` را گم کنید** تمام فیلدهای مهروموشده برای همیشه غیرقابل خواندن‌اند — بک‌آپ بدون آن بی‌ارزش است. یک کپی **خارج از سرور** نگه دارید.
- **اگر `master.key` لو برود** فیلدهای مهروموشده قابل خواندن می‌شوند. هرگز در گیت کامیت نکنید؛ `.gitignore` مخزن از قبل آن را مستثنی کرده.
- **بازیابی** روی یک سرور تازه: هایپردی‌ان‌اس را نصب کنید، سرویس را متوقف کنید، هر دو فایل را در `/opt/hyperdns/` بریزید، سرویس را استارت کنید. ارتقا از نسخه‌های قدیمی‌تر فرمت داده‌ها را در اولین اجرا تبدیل و بعد یک بار فایل را بازنویسی می‌کند، تا صفحات آزادشدهٔ حاوی متن قدیمی از دل نسخهٔ پشتیبان قابل استخراج نباشند.

رمز عبور ادمین در **هیچ‌کدام** از این دو فایل نیست — فقط یک تأییدکنندهٔ PBKDF2-HMAC-SHA256 (با ۶۰۰٬۰۰۰ دور تکرار). هیچ‌کس، حتی شما، نمی‌توانید آن را بازیابی کنید؛ فقط قابل تغییر است. اینکه کدام فیلدها رمزنگاری می‌شوند و کدام عمداً شفاف‌اند در [SECURITY.md](SECURITY.md) مستند شده.

## ۱۶. عیب‌یابی

| نشانه | بررسی کنید |
| :--- | :--- |
| **نصاب می‌گوید صدور گواهی پنل ناموفق بود** | رکورد A باید از *بیرون* به این سرور حل شود؛ پورت ۸۰ تا انتها باز باشد (شامل فایروال ابری ارائه‌دهنده)؛ هیچ سرویس دیگری روی ۸۰ نباشد. نصاب دلیل را می‌گوید. |
| **مسیر ادمین را گم کردم** | `hdns status`، یا `journalctl -u hyperdns | head` — در هر استارت دوباره چاپ می‌شود. |
| **رمز عبور ادمین را گم کردم** | قابل بازیابی نیست، فقط قابل تغییر — نصاب را با `HYPERDNS_FRESH=1` اجرا کنید (اول نصب قدیمی را آرشیو می‌کند)، یا باینری را با یک کانفیگ تازه استارت کنید. |
| **مشترک می‌گوید «هیچی کار نمی‌کنه»** | آیا آی‌پی‌اش را ثبت کرده؟ لینکش `/sub/<token>` است؛ رمز جداگانه است. در **Clients** آی‌پی متصل فعلی‌اش را بررسی کنید، و از او بخواهید روی شبکه‌ای که دارد دوباره ثبت کند. |
| **کوئری‌ها جواب می‌دهند ولی بازی هنوز لگ دارد** | در **Live Stream** دامنه‌های آن بازی را ببینید: `PROXY` (از پراکسی SNI می‌گذرد) یا `DIRECT`؟ جواب `DIRECT` یعنی پریست آن بازی خاموش است. |
| **دانلودها روی ۰ بایت بر ثانیه گیر کرده‌اند ولی صفحهٔ استور باز می‌شود** | همان یک کاربردی است که `enable_downloads` برایش وجود دارد — خط کاربر اصلاً به CDN نمی‌رسد. روشنش کنید، یا فقط CDN مشخص را به **Custom Proxied** اضافه کنید. |
| **قانون را تغییر دادم، چیزی عوض نشد** | پاسخ‌های کش‌شده تا پایان TTL مسیر قدیمی را نگه می‌دارند. **Flush Cache** (ساید‌بار) یا `hdns flush`. |
| **پورت ۵۳ در حال استفاده است** | `systemd-resolved`. نصاب خودش انجام می‌دهد؛ اگر دستی حذف و نصب کردید، `/etc/systemd/resolved.conf.d/hyperdns.conf` را بررسی کنید. |
| **داشبورد باز می‌شود ولی `hdns status` می‌گوید لیسنری جواب نمی‌دهد** | فایروال. با `ss -lnup` به‌صورت محلی و با یک تستر پورت از بیرون راستی‌آزمایی کنید. |
